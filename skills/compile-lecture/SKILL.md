# Compile Lecture - 课程讲次汇编

你将把用户提供的一讲课程 PPT 图片，整理为两个相互独立、各自成文的产物：**知识点笔记**（为预习、学习、复习而设计的学习材料，含应试特征）与**博客章节**（发布内容，教材式整理体，不含应试特征）。你的转述纪律是忠实于 PPT 等本地材料内容，一般不联网核实，但要对明显笔误保持警觉。

## 前置

如果用户**还没有**提供以下信息，你需要首先向用户提问：

### Q1：材料来源

需要分析的课件是哪一个？按材料形态分三条路径处理：

- **图片目录**（已导出课件每页图片）：可直接前往 Q2。
- **PPT 文件**（.pptx/.ppt）：你需要引导用户将 PPT 导出为每页图片（通过 Microsoft Office 的文件-另存为-JPEG 方式），才可继续分析。
- **PDF 文件**：运行自带的转换脚本 `<此SKILL目录>/scripts/pdf2img.py`：`python <此SKILL目录>/scripts/pdf2img.py <PDF路径>`。该脚本自洽：会自动安装 pymupdf 依赖到脚本旁的 `.deps/` 目录，不污染用户的环境；会输出 JPG 格式图片到课件目录旁的 `pages/` 子目录（或使用 `-o` 指定自定义输出目录），文件名按页码命名形如 `p001.jpg`。

### Q2：课程信息

当 Q1 已经解决后，你可粗略根据文件名和首张 PPT 来判断课程的基本信息，然后寻求用户确认以下细节：

- 准确的课程名
- 课程名的英文 slug
- 要求的产物类型（仅笔记？仅博客？笔记和博客都要？）
- 目标博客的分类和 tag（仅当已选了博客时）

随后，在 PPT 图片的根目录建立课程档案 `course-manifest.md`，必须包含：

1. 基本上下文信息：课程名与 slug、博客分类；
2. 追溯性信息：合集文章路径、讲次计数、修订时间；
3. 内容性信息：术语表、存疑项汇总。

后续调用先检查档案是否存在，一般不要重复询问已敲定的内容。

## 阶段一：读图与结构化

- **顺序**：按文件名自然排序确定页序。若文件名乱序、页序需要靠内容推断，凭借推断结果工作。
- **唯一输入源原则**：所有原始图片必须*由你亲自阅读*，不得派遣子 agent 代读。因为图像内容的细节（重点标记、强调色、页间连贯性、笔迹与口吻）极易在子 agent 的转述中丢失上下文信息。你逐张阅读，可直接吸收页级结构化条目：知识点、术语、图表描述、公式（LaTeX）、存疑标记，以及*应试信号*——本页在讲课中的篇幅占比、是否含重点标记（"重点"、记号、★、下划线）、是否使用强调色高亮。
- **高难任务外派**：子 agent 的适用于两类任务——*核对和探索*（如术语一致性核对、存疑项复核、产出物交叉校对、深度思考或研讨），以及*解决较复杂的题目*（例如做数学例题、整理解题过程）并输出结果。分配子 agent 的核心目的是将长线思考内容进行外派委托，使得你更专注于眼前工作。
- **一致性对齐**：读图过程中随时做术语初筛：与课程术语表冲突的，以术语表为准并记录差异。若用户在档案中主动供给考纲、往年卷或划重点，按纲覆盖信号推断；否则仅以应试信号标注考点。

## 阶段二：提纲与关键图批发（闸门）

先计划，后动笔。使用提问工具向用户一次呈现：

- 两产物提纲：笔记的章节目录；合集文章本讲新增章节（`## Lxx <讲标题>`）的结构；
- 关键配图候选清单：编号 + 图片页码 + 保留理由。只列信息量大或文字无法重建的图（流程图、示意图、图表）。

用户批发编号后：将入选图片**复制**（非移动）到博客文章的同名资产目录，文件名加 `Lxx-` 前缀防止跨讲撞名，供后文以相对路径 `./Lxx-xxx.png` 引用。

## 阶段三：撰写（串行）

两产物独立成文，写作串行进行。

### 知识点笔记

整份笔记为**预习、学习、复习**三种场景全适配设计：预习者需要知识地图，学习者需要与课堂对应的讲解与例题，复习者需要考点、辨析与自测。笔记不是 PPT 的流水式记录。

- 落盘到图片目录所在的父目录的 `notes-<图片目录名称或其他合适名称>.md`。
- 正文按**知识结构逻辑重组**分章，不按页序流水排布；每个知识点附原 PPT 页码，供回查与课堂对照。
- 忠实转述为主；存疑内容使用 `[!WARNING]` 块进行标注，需要注意图片分析时可能丢失的 PPT 动画细节。
- **考点标注**：依据应试信号行内标注（如 `【考点：强调色标注】`、`【考点：篇幅占比高】`），不虚构考频。
- **例题**：行内紧随相关知识点。优先提取 PPT 原题与原解；仅当某考点信号强烈而 PPT 无合适例题时，才允许自编少量例题，并显式标注`（自编）`。
- **易混淆辨析**：使用 `[!CAUTION]` 块对易混概念做对比辨析（相似术语、易混公式，或其他 PPT 中已标记为易混淆概念的内容）。
- 尾部依次集中：**QA 自测题**（问题与折叠答案，供考前提问式自测）、**公式汇总表**（本讲全部公式）。
- 写作前读取课程术语表并保持术语一致；新术语增量回写档案。

### 博客章节

- 以**教材式整理体**（知识点铺陈、定义 + 例子，面向后来的学习者）向合集文章追加本讲章节。
- 模仿现有博客的 front-matter 写法，仅在合集文首次创建时生成（`toc: true`、categories、tags、date）。
- 只写确定内容，**存疑项不进入博客**。
- 不写 `[!WARNING]` 等特化块。
- 关键图以相对路径引用，并配文字说明。

## 阶段四：收尾

- **更新与维护课程档案**：务必按照前述要求对课程档案文件进行主动维护。
- 向用户汇报两产物路径与增删行数，然后停下等待人工审阅。遇阻碍不可越权，使用提问工具集中提问。
