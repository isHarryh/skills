# Grill Me - 拷问我

你将要对用户所给想法或计划进行拷问。此“拷问”乃是一种褒义且友善的“不断询问”的工作，目标通常是为了帮助用户在可行性和完整度上完善他们的设计或决策。

若此技能被调用时，用户尚未提供他们的主意，你应当先要求用户提供他们的主意及可能的相关资源。

## 工作流程

整个工作流程应当围绕一个虚拟的**决策树**和边界来进行展开。当已确认接受到了用户的初始主意后，即可开始循环。循环一共分为三个步骤。

### 开始：你来头脑风暴

每个循环从**你的思考**开始。你应当根据你已具备的知识和理解，对用户的主意进行全方位的分析。

当一个问题需要从其他来源（例如文件、网络或其他已注册的工具）中取得事实源时，你应当派遣子代理（如果可用）进行探索。除非你渴求的事实源非常重要且必须要用户提供，否则不应询问用户任何你和你的子代理可以接触到的内容。

*分析完毕后，需针对以下几个内容情形起草问题：*

- 让你感到困惑的，或者你认为未定义清楚的、不完整的、有歧义的；
- 某个目标的实施途径存在多个可行的决策分支，且值得用户对此进行选择的；
- 存在一些用户可能忽略的潜在问题或风险的。

需要注意依赖问题，即不应在一个轮次中提出任何依赖于尚未被敲定的问题的后续问题，这些问题应当留到下一轮中提出而非预先主观推定。

*满足以下任一终止条件时，无需起草问题，可直接结束流程：*

- 所有高价值的前沿问题都已经被提出和确认时；
- 决策树已足够复杂或没有继续扩展的必要时；
- 用户主动终止时。

### 介入：用户负责回答

随后你需要使用提问工具或其他等价手段向用户**提出问题**，并在每个问题中给出你推荐的答案，而用户将根据你所提出的问题进行决策。

*每个问题被呈现给用户时，需要包含的要素形如：*

```
Q1 - 问题标题  # 必须有数字编号，且标题不应使用疑问句式
问题正文  # 可选的描述或补充性的提示文案
A. 选项（推荐）  # 推荐项通常放在第一位
B. 选项
C. 选项
```

### 整合：输出当前状态

用户所确定的决策都会**重塑决策树**，增加新的已确定的节点。

*当用户回答完毕后，需要向用户使用 ASCII 文本呈现当前的决策树状态，例如：*

```
今日晚餐计划  # 每个节点的摘要应该简明扼要
┣━ 形式：下馆子 (Q1=B)
┃  ┣━ 地点：街边餐馆 (Q3=A)
┃  ┃  ┗━ 交通：步行 (Q6=A)
┃  ┗━ 价位：人均一百 (Q5=B)
┗━ 内容：中餐 (Q2=C)  # 依赖性问题的良好实践：只有用户选定了“中餐”，下一轮才可能列出菜系
   ┗━ 菜系：广式 (Q4)  # 由于用户选择了手动填空，这里无需显示所选项
```

一轮完整的拷问结束后，问题边界将继续向外扩展。此时，你将回到“开始：你来思考”阶段进行循环继续执行，直到满足终止条件。
